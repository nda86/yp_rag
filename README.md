## Окружение и структура проекта

### Установка окружения

Предусмотрено два способа установки зависимостей проекта.

**Способ 1. Через uv (рекомендуется)**

Установить зависимости проекта с учётом `uv.lock`:

    uv sync

**Способ 2. Через pip**

Установить зависимости из `requirements.txt`:

    pip install -r requirements.txt

Оба способа позволяют подготовить окружение для запуска Jupyter Notebook и выполнения экспериментов.

### Аппаратное и программное окружение

Из-за возникших проблем с доступом к виртуальным машинам Яндекса, все этапы исследования и разработки выполнялись локально на ноутбуке **MacBook Pro 16" с процессором Apple M1 Max и 32 GB объединённой памяти**.

Для генерации ответов использовалась локальная языковая модель **Qwen3.5-4B** в формате GGUF с квантизацией `Q4_K_M`. В качестве сервера инференса использовался `llama-server` из проекта `llama.cpp`.

Сервер запускался следующей командой:

    llama-server -hf unsloth/Qwen3.5-4B-GGUF:Q4_K_M --host 127.0.0.1 --port 8080 -ngl 99 -c 4096 --jinja --log-file ~/llama-server.log

Основные параметры запуска:

| Параметр | Значение | Назначение |
|---|---|---|
| Модель | `Qwen3.5-4B-GGUF:Q4_K_M` | Языковая модель с 4 млрд параметров, квантизированная в Q4_K_M |
| `--host` | `127.0.0.1` | Локальный сетевой интерфейс сервера |
| `--port` | `8080` | Порт для запросов к модели |
| `-ngl` | `99` | Количество слоёв модели, выгружаемых на GPU |
| `-c` | `4096` | Размер контекстного окна в токенах |
| `--jinja` | — | Использование шаблона чата модели |
| `--log-file` | `~/llama-server.log` | Файл для записи логов сервера |

Генерация ответов выполнялась локально, без обращения к внешним API языковых моделей.

### Структура проекта

Работа разделена на три Jupyter Notebook. Каждый ноутбук отвечает за отдельный этап исследования и разработки RAG-системы.

| Ноутбук | Назначение | Содержание |
|---|---|---|
| `Audit.ipynb` | Исследование и очистка данных | Первичный анализ корпуса документов, изучение структуры и качества данных, выявление проблем и подготовка корпуса к дальнейшей обработке. |
| `Chunking.ipynb` | Эксперименты с чанкингом | Сравнение стратегий разбиения документов на чанки, анализ влияния размера и перекрытия фрагментов, выбор итоговой стратегии. Формирование финального набора чанков и вычисление эмбеддингов. |
| `RAG.ipynb` | Разработка и оценка RAG-системы | Реализация основного пайплайна: Dense Retriever для поиска релевантных фрагментов, Reranker для их дополнительного ранжирования и LLM для генерации ответов на основе найденного контекста. Проведение экспериментов и оценка качества системы. |

### Последовательность выполнения

Работа организована как последовательный процесс:

1. **Audit** — исследование исходного корпуса, анализ качества и подготовка данных.
2. **Chunking** — эксперименты с разбиением документов, выбор стратегии чанкинга и подготовка векторного представления корпуса.
3. **RAG** — построение поисково-генеративной системы, настройка компонентов и оценка итогового качества.

Такое разделение позволяет последовательно исследовать качество исходных данных, влияние стратегии чанкинга на результаты поиска и эффективность итоговой RAG-системы.
